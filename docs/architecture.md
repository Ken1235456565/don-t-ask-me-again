# 技术架构：macOS 规划

## 文档状态

以下为 Mac 首版的拟议架构，尚未创建工程、实现接口或完成技术验证。M0 技术验证完成后再冻结系统要求、依赖版本和数据格式。本步骤不执行 M0。

## 技术选择

| 层级 | 拟采用方案 | 决策边界 |
| --- | --- | --- |
| Mac 客户端 | Swift + SwiftUI，必要时使用 AppKit | 只建立 macOS 产品目标，不提前建设移动端 UI |
| 本地推理 | 优先验证 Foundation Models 的设备端模型 | 显式限定本地执行；按运行时可用性决定是否启用 |
| 检索与匹配 | 结构化查询、规则匹配与本地模型结合 | 确切值读取和格式校验由确定性逻辑完成 |
| 结构化存储 | SQLite；SQLCipher 作为数据库加密候选 | 在 M0 验证依赖许可、加密覆盖、迁移和分发可行性后定案 |
| 文件存储 | 应用容器内的加密文件，候选使用 CryptoKit | 原文件、提取文本、索引和临时文件都纳入保护范围 |
| 密钥与解锁 | Keychain + LocalAuthentication | 明确密钥可访问条件与恢复策略；不把解锁界面当作加密本身 |
| 文件解析 | PDFKit + Vision | 本地解析 PDF 和图片；解析失败时保留手动录入路径 |
| 网页填写 | 随 Mac App 分发的 Safari Web Extension | 用户主动触发，按网站最小授权 |
| 扩展通信 | Native Messaging；必要时使用受限 App Group 通道 | 扩展不持有长期解密密钥或完整资料库副本 |

暂以 **macOS 26 及以上**作为技术验证起点，并在 M0 决定最终最低版本与设备范围。Apple 说明 Foundation Models 随 macOS 26 提供，并依赖兼容设备上的 Apple Intelligence；“系统版本满足”不能单独作为模型可用的判断条件。[Apple 官方说明](https://www.apple.com/newsroom/2025/09/apples-foundation-models-framework-unlocks-new-intelligent-app-experiences/)

应用应检查模型运行时状态。模型不可用时仍提供手动资料管理和确定性检索，明确提示智能功能不可用。MLX / Core ML 替代模型留待后续评估，首版不同时集成多个推理后端。

## 模块职责

| 模块 | 职责 | 不授予的权限 |
| --- | --- | --- |
| Vault | 维护事实、来源、文件和时间线；执行加密读写 | 不直接接受网页指令 |
| Retrieval | 按明确字段和用途查找最小必要资料 | 不向网页返回整个资料库 |
| Brain | 理解问题与字段含义，生成候选匹配 | 不持有数据库密钥，不任意查询全部记录，不批准披露 |
| Policy | 检查请求来源、资料库状态、字段范围与用户授权 | 不以模型输出替代用户许可 |
| Review | 展示候选答案、来源、目标与披露范围 | 不默认批准所有字段 |
| Fill Executor | 执行当前页面上已批准的字段写入 | 不提交表单、不签名、不接管登录 |
| Audit | 记录最小化的本地操作结果 | 不持久化填写值或模型上下文 |

模型优先接收字段描述与候选资料的类型、来源标识等必要信息。证件号码等精确值由受控检索与填写流程处理；不为理解字段而默认把完整证件或全部资料送进模型上下文。

## 数据模型草案

- **Person / Fact**：个人主体、字段类型、值、确认状态、有效期、版本。
- **TimelineEntry**：地址、教育或工作事件及其起止时间，保留缺失与重叠状态。
- **SourceDocument / Evidence**：加密文档、页码或原文位置、提取方式及确认记录。
- **FillRequest / FillPlan**：当前页面字段描述、候选事实引用、预览修改与跳过原因。
- **DisclosureGrant**：一次填写所批准的来源、页面、字段、值版本、有效期与执行状态。
- **AuditEvent**：时间、目标 origin、字段类型、批准或拒绝结果及执行状态。

首版只有本机资料库，不设计云端账号、远程身份映射或同步协议。模块保持清晰边界即可，不为移动平台提前引入共享 UI、跨平台工程或复杂同步抽象。

## Safari 与本地资料库之间的边界

1. 用户主动操作扩展；扩展在 Safari 已授予的权限范围内读取当前表单。
2. 内容脚本经扩展后台和 Native Messaging 发送字段描述，不开放“返回全部资料”或任意数据库查询接口。
3. 原生侧校验消息结构、来源上下文和资料库解锁状态，生成填写计划。
4. 用户审核具体值与目标后，Policy 产生一次性、短时授权；授权绑定 origin、标签页、frame、页面实例、字段及值版本。
5. 执行前重新检查上下文和字段。导航、切换 origin、字段变化、锁定、取消或到期均使授权失效。
6. 只向执行端返回本次批准的数据；填写结束或失败后清理临时数据并销毁授权。

origin 与页面标识必须取自扩展运行时提供的上下文，不信任网页自报的 URL。首版不填写跨来源 iframe、隐藏字段或无法可靠确认目标的字段。无法验证来源与授权绑定时拒绝执行，并在 M0 验证所需 API 能力。

Apple 的 Safari 权限文档建议优先采用 `activeTab`、按网站或可选权限，减少访问范围；本项目不默认申请所有网站访问权。[Safari 权限文档](https://developer.apple.com/documentation/safariservices/managing-safari-web-extension-permissions)

Safari 扩展的网页脚本、原生扩展和宿主 App 分属不同执行环境，通信需通过指定机制完成；具体消息通道与 App 生命周期行为需要在 Mac 上验证。[Native Messaging 文档](https://developer.apple.com/documentation/safariservices/messaging-between-the-app-and-javascript-in-a-safari-web-extension)

## 安全与恢复约束

- 网页、PDF 和导入文本均按不可信输入处理，不能改变资料访问策略或扩大工具权限。
- 模型只生成建议；字段校验、授权和执行由独立逻辑控制。
- 数据库、附件、全文索引、日志、缓存、数据库辅助文件与备份均需检查是否泄露明文。
- 锁定后撤销授权、关闭解密访问并尽可能清理上下文；不能宣称可保证擦除所有运行时内存副本。
- 加密备份需独立恢复机制，例如以用户备份口令封装数据密钥；参数和格式在技术验证后确定。
- 删除当前资料不等于删除用户另存的备份；界面需说明备份的独立生命周期。
- 不默认接入遥测、远程崩溃上传、云推理或服务端资料存储。

以 Mac App Store 分发为目标，后续必须在沙盒、签名和实际扩展生命周期条件下验证方案。本文不把采用某种框架视为已满足商店审核要求。
